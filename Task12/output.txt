TASK 12 – Remote monitoring and cloud records
DECISION: MODIFY the original design.
RETAIN: local hard-real-time alarm path on home and bedside devices; local alarms do not depend on internet/cloud round trips.
ADD: secure device identity, secure boot, signed firmware, encrypted local storage and certificate rotation.
ADD: mutually authenticated TLS, API gateway, message broker, schema validation, rate limiting and store-and-forward queue.
CLOUD: distributed records service with tenant isolation, RBAC, encryption, audit, multi-zone availability and tested backups.
INTEGRATION: hospital connectors, identity federation, agreed healthcare APIs, consent/purpose controls and data minimisation.
TRADE-OFFS: cloud scale and sharing versus network dependence, provider risk, privacy obligations, cost and integration complexity.
OFFLINE: device keeps alarm local and queues timestamped telemetry for later synchronisation.
