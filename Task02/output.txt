TASK 2 – OS type selection
Bedside monitors: Hard real-time embedded OS
  Rejected alternative: General desktop OS: no inherent hard deadline guarantee
Nurses' tablets: Handheld/mobile OS
  Rejected alternative: Desktop OS: greater resource and battery demand
Doctors' workstations: Desktop OS
  Rejected alternative: Hard RTOS: not needed for interactive office applications
Patient database: Clustered server OS with fail-over
  Rejected alternative: Single server: single point of failure
MRI imaging server: Multiprocessor OS using SMP
  Rejected alternative: Single processor: less parallel capacity
Partner hospitals: Distributed system
  Rejected alternative: Local-only system: cannot coordinate shared records

SMP vs AMP
SMP: processors share one OS image and memory; simpler parallel workload scheduling.
AMP: processors may have assigned roles/OS instances; useful for isolation but adds coordination.

Database alternative
Single multiprocessor host: potentially strong throughput, but host/power/storage failure stops service.
Cluster: extra cost and operational complexity, but redundant nodes and fail-over improve availability.
